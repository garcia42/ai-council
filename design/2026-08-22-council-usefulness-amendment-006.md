## Invalid events cannot steal a valid lifecycle

A report-invalid physical initiation receives its own incomplete denominator position but cannot
become the preferred parent of later strictly valid attempt, seat-finished, completion, or outcome
records. When a strict-valid lineage exists, later records remain associated with it. This remains
true when the invalid duplicate is physically interleaved between the valid initiation and its
later lifecycle records. Orphan and late-fill reporting remains visible without suppressing a
canonical eligible issuance.

Report-time custody covers every planned seat input artifact, not only submitted-seat result
artifacts. An abstained or unavailable blind seat retains its exact run-bound prompt, and deletion,
tampering, or aliasing of that prompt is an artifact-integrity failure that excludes the run from
headline analysis. Terminal seat state does not waive input custody.

## Complete lock and standalone boundaries

Every derived per-ledger lock is part of the write set for containment and fixed-host authority.
Lock creation and opening reject symlinks and non-regular files, including dangling symlinks whose
targets lie inside live state. A caller cannot place a nominally local ledger beside a lock alias
that creates or mutates a live path.

Explicit standalone paths do not silently acquire the live coordination lock. When all requested
writes are outside live council state, an omitted coordination lock is resolved to an isolated
local lock (or rejected with an explicit-path requirement); it never opens the live default.
Validation-only commands do not acquire write authority or create a lock.

## Rehearsal inode isolation and install mutation containment

Tests run inside copied-live rehearsal may not link, open for write, chmod, or otherwise mutate a
live evidence inode. Runtime-contract alias tests use staged or temporary copies only. The
before/after guard includes inode link count and ctime as defense in depth, but an unchanged final
state is not a substitute for denying the live mutation in the first place.

Installer containment is enforced at each mutation boundary, not only during an earlier render or
validation pass. Replacing a validated ancestor with a symlink before target replacement must fail
without writing outside the resolved installation root. Rollback uses the same contained mutation
primitive and cannot follow a swapped ancestor into an outside target. Backup durability and
successful-replacement fsync guarantees from amendments 004 and 005 remain in force.
