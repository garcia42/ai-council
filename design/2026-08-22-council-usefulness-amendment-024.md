## Only authenticated sidecar resolutions may grade V2 outcomes

A physical `outcome-resolution` row in the main capture ledger is never resolution evidence for a
V2 outcome. Headline Brier scoring and resolved-outcome counts consume only resolution-sidecar rows
that passed the complete V2 schema, outcome-fingerprint binding, provenance, date, evidence,
resolver, reviewer, method, timestamp, and duplicate-consistency checks. Ledger-origin resolution
rows remain diagnostic invalid records and cannot change any score or state. An integration
regression appends an otherwise plausible legacy-looking resolution row to the main ledger with no
sidecar and requires zero resolved V2 outcomes, no Brier score, and an explicit invalid diagnostic.

## Installer custody includes source templates, backup descendants, and reports

Repository identity is not continuing proof of source-template bytes. Every installed source
template is opened without following links, pinned, digested, rendered from retained descriptor
bytes, and revalidated through runtime publication and success. A deterministic substitution after
repository identity validation must fail or install the originally pinned bytes; it must never
publish substitute bytes that later pass the wrapper's integrity check.

All backup descendants are created relative to pinned no-follow directory descriptors. Replacing
the unique backup pathname with a directory or symbolic link during nested creation must not create
anything outside the retained backup inode. Retained-custody inventories are likewise created,
synchronized, authenticated, and revalidated relative to the retained backup descriptor. A
swap-and-restore during report publication must fail before success or leave the authenticated
backup containing the exact inventory named by the result. Report inode and content identity remain
bound through final verification.

## JSONL publication is identity-conditional and cleanup is non-destructive

The crash-atomic JSONL writer's final namespace mutation is conditional on the destination identity
validated for the append transaction. Destination substitution between validation and publication
must fail without overwriting the concurrent inode. Temporary-name cleanup is also identity-bound:
a foreign inode that repopulates the temporary name is never unlinked, overwritten, or silently
claimed as the writer's file. Deterministic regressions cover both cuts and require the concurrent
objects to remain recoverable while the append reports failure. The design may retain transaction
escrows rather than destructively clean up a name whose ownership is no longer certain.
