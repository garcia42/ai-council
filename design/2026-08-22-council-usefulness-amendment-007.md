## Forecast provenance and prospective issuance

Every submitted seat's exact visible JSON output contains a structured capture declaration binding
its seat ID and shared-outcome probability. The sealed completion probability must exactly equal
that captured declaration. An operator cannot transcribe, reinterpret, or substitute a different
probability after the reviewer output is captured. Structured no-findings uses the same declaration
and adds its no-findings kind rather than creating a separate unbound path.

`finalizedAt` is the V2 forecast issuance boundary and must precede the shared outcome's
`resolutionDate`. A completion on or after that date is schema-invalid and never enters headline
scoring. The existing boundary-ordering and evidence-cutoff requirements remain additive.

Schema validation itself, not only the integrated runtime writer, exact-binds every planned blind
brief to that seat result's persisted input artifact. It also recomputes the complete per-seat input
manifest from persisted result references and requires the attempt's bound manifest digest. Thus
tolerant report ingestion cannot accept a canonical-looking substituted prompt or seat reference.

## Invalidation and resolution integrity

If normally handled incident metadata itself triggers secret preflight, the system appends a
sanitized `secret-detected` invalidation while the coordination and ledger locks remain held. The
fallback contains no caller bytes and cannot leave an otherwise eligible run valid merely because
its proposed operator or evidence text was unsafe. The process-crash qualification in amendment
004 remains unchanged.

The V2 resolution sidecar contains only recognized V2 outcome-resolution events. Every resolved
outcome ID must have an observed V2 attempt issuance in the mixed ledger. Orphan resolutions and
unrelated event kinds fail the report rather than disappearing from counts or scores.

## Mutation identity and activation boundary

Ledger mutation pins and traverses parent directories component-by-component without following
symlinks, and validates the opened target inode immediately before writing. Existing ledger
hardlink aliases are rejected. Append, atomic replace, recovery, and rollback use pinned directory
descriptors and retain their lock/fsync guarantees. A pathname ancestor swap after CLI authority or
activation classification therefore cannot redirect a nominally local write into live state.

The hardcoded live-activation blockers also apply at the public runtime activation writer boundary,
not only in CLI dispatch. Direct library use against the OS-account live council ledger cannot
append activation in this release; explicit temporary ledgers remain available for tests and
standalone use.

## Rehearsal mutation denial

Copied-live runtime-contract subprocesses require no access to enumerated live evidence paths. They
deny live-path opens and all supported audited path mutations before syscall, including permission,
ownership, timestamp, truncation, link, rename, removal, and directory mutations. Rehearsal must
execute representative proofs, including the previously missed `chmod` path. The final inode,
link-count, ctime, and content comparison remains defense in depth rather than the primary barrier.

Live V2 activation remains disabled by the independent-audit and off-host-durability blockers.
