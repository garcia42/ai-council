## Visible canonical forecast request

A digest commits to a request but does not disclose it. Every planned seat's visible prompt
therefore contains one machine-parseable canonical request block with the actual run ID, outcome
ID, outcome fingerprint, evidence cutoff, claim, resolution date, resolution procedure,
materiality, and actions if true or false. The request digest is computed from that exact block.

Writer-time and report-time checks parse the retained prompt block and require exact equality with
the sealed attempt. Opaque binding tokens remain useful custody evidence but cannot substitute for
showing the reviewer the forecast target. All planned seats receive the same canonical block; a
prompt visibly asking a different question is invalid even if it repeats the correct digest.
